## 1. 赛题拆解：把"三道题"翻译成"三个工程问题"

| 赛题要求 | 本质工程问题 | 我们的对应产物 |
|---|---|---|
| 任务 1：梳理学习内容与要求，标明课标、教材、题目出处 | 建立 **可追溯的知识谱系**（课标条目 → 教材页 → 观察指标 → 题目） | `task1_knowledge_structure.json` + `knowledge_graph.html` |
| 任务 2：整理与质检数据，给个体/群体学情摘要，指出需巩固内容、差异、共性，说明信息不足 | 建立 **带证据门槛的诊断**（清洗留痕 + 证据链 + 不确定性表达） | `statistics.json`、`mastery_matrix.json`、`student_profiles.json`、`error_diagnosis.json`、`data_quality_report.json` |
| 任务 3：给出具体学习内容/练习/活动建议，含材料、理由、先后顺序、调整条件 | 建立 **可执行、可验证的教学决策**（题号级推荐 + 分步提示 + 过关判据） | `task3_recommendations.json`（3 个典型案例 + 37 人轻量建议 + 班级建议） |

**设计上的一个关键决定**：三个任务共用**同一套 9 个观察指标**作为主键。任务 1 用指标组织内容，任务 2 用指标组织证据，任务 3 用指标组织练习——避免"三张皮"，这也是答辩时最好讲的一条工程判断。

## 2. 系统总览

### 2.1 分层架构

```
┌──────────────────────────────────────────────────────────────┐
│ 交互层  Streamlit 智能体外壳（唤醒 → 选身份 → 选对象 → 对话/页面）│
│        学生视角：对话/我的学情/学习建议/知识地图/成果文件          │
│        教师视角：对话/班级概览/学生名单/数据质量/成果文件          │
├──────────────────────────────────────────────────────────────┤
│ 智能体层 07V2：Coordinator（规则路由 + 会话记忆 + 复合级联）        │
│        ├ DiagnosisAgent   诊断（掌握度/证据/顽固错误）            │
│        ├ RecommendationAgent 建议（分层推荐 + 分步提示）           │
│        ├ LectureAgent     讲评稿（必讲评分点 + 两班差异）          │
│        ├ ClassAgent       班级对比                              │
│        └ ValidatorAgent   四道闸门校验（证据ID/阈值/不泄答案/一致） │
│        Trace：每步落一条执行轨迹（可回放、可复核）                 │
├──────────────────────────────────────────────────────────────┤
│ 引擎层 09 知识谱系 ｜ 01 统计 ｜ 02 掌握度 ｜ 03 错因 ｜ 08 建议生成  │
│        统一"证据门槛 = 3 条"的口径，所有结论必须挂记录编号          │
├──────────────────────────────────────────────────────────────┤
│ 数据层 output/*.json（机读）+ *.html（人看）+ llm_cache（可复跑）  │
└──────────────────────────────────────────────────────────────┘
```

### 2.2 数据流

```
赛题 CSV（40 人 / 806 行 / 54 题）
   └─01 清洗 → cleaned_data.json（790 条有效 + 8 条规则命中留痕）
        ├─02 知识追踪 → mastery_matrix.json / student_profiles.json
        ├─03 错因诊断 → error_diagnosis.json（385 条，C1–C6）+ 模式汇总
        ├─09 知识谱系 → task1_knowledge_structure.json（3 主题/9 指标/54 题）
        ├─08 建议生成 → task3_recommendations.json（3 案例 + 37 人 + 班级）
        ├─05 知识图谱 → knowledge_graph.html（80 节点，可交互）
        └─06 仪表盘（可选，默认不在流水线内）→ dashboard.html
              └─07 + UI：把以上全部接成"能对话的智能体"
```

### 2.3 为什么用"规则 + 本地模型"而不是"纯大模型"

- 统计数字必须**可复算**：评审随时可以拿 CSV 复核，大模型算错一次就致命；
- 因此采用 **"规则算事实、模型管表达"**：LLM 只做语义归因与话术改写，且输出必须过校验（见 §6）；
- 本地模型（`deepseek-r1:8b`，Ollama）意味着**断网可演示**、**数据不出本机**，符合赛题"数据不得外传"。

## 3. 任务 1 的实现：知识谱系（可追溯）

### 3.1 做法

以 **观察指标** 为骨架，把四类材料对齐成一行：

| 字段 | 来源 | 示例 |
|---|---|---|
| 主题 / 指标 | `课程要求.csv` | T01 / T01I2 识别同类项、去括号并化简 |
| 课标条目与页码 | 课程标准 2022 | CR01 · 文件第 62 页 / 正文第 55 页 |
| 教材段落 | 人教版切片 | 上册 68—109 页（B05 切片） |
| 对应题目 | 题目表 | Q004、Q005、Q008、Q009、Q010、Q012、Q015、Q016、Q017、Q018（10 题） |
| 题量与分值 | 统计 | 10 题 / 12 分 |
| **证据密度** | 790 条记录 | 高（1 个指标）/ 中（5）/ 低（3） |

产物 `task1_knowledge_structure.json` 自带 `meta`（生成方式、阈值、时间）与 `summary`（3 主题 / 9 指标 / 54 题 / 790 条证据），**可机读、可复核**。

### 3.2 两个能讲的设计点

1. **"证据密度"作为一列**：评审一眼能看到哪些指标结论可靠（中高 6 个）、哪些只能算线索（低 3 个）。这是把"数据支持度"显式化。
2. **双向导航**：界面里点任一指标，同时看到"课标怎么要求 / 教材在哪页 / 有哪些题 / 有多少证据"；知识图谱（80 节点）提供全局视图。

> PPT 建议：放一张"四列联动"截图 + 一张知识图谱截图，配一句"每个知识点都能追溯到课标页码和教材页码"。

## 4. 任务 2 的实现：证据门控的学情诊断

### 4.1 数据治理：先讲清"我们怎么处理脏数据"

赛题明确要求说明缺失、异常、重复的处理方式。我们把它做成**可复跑的 8 条规则**，每条都输出命中记录编号：

| 规则 | 命中 | 处理 |
|---|---|---|
| R1 得分 > 满分（如 10/1、4/3） | 2 条 | **保留源分 + 标记**，统计时按满分截断，源值可追溯 |
| R2 评分点之和 ≠ 总分 | 3 条 | 标记为成绩冲突（DR0133 / DR0361 / DR0535），源分保留 |
| R3 同一作答事件多版本 | 7 组 14 行 | 取最新修订版本 |
| R4 待评分 | 6 条 | 隔离，不进入得分统计 |
| R5 未作答 | 5 条 | 单独标记，**不等于答错** |
| R6 题目不在该节点可用范围 | 1 条 | 节点口径冲突，剔除对照 |
| R7 记录主题 ≠ 题目主题 | 1 条 | 以题目表为准修正 |
| R8 答案与参考答案一致却判 0 分 | 1 条 | 标记评分冲突，不作能力证据 |

**关键设计：不静默改数据。** 三条成绩冲突（`DR0133` 3 分 / 评分点和 2、`DR0361` 10/1、`DR0535` 4/3）**源分原样保留**，只加 `conflict` 标记；口径统计时按满分截断。这样"原始值 → 处理值 → 统计值"三段都可回溯，`verify.py` 会同时校验"冲突记录均已标记"和"源分未被改写"。

**这张表就是"数据处理"评分项的直接证据**——不是"我们注意了数据质量"，而是"每条异常都能点出记录号"，而且命中数已经**写进产物并由脚本校验**：

```
R1=2  R2=3  R3=14  R4=6  R5=5  R6=1  R7=1  R8=1
（verify.py：质量复核规则 = 8，命中数符合源数据 ✅）
```

### 4.2 掌握度：为什么只给 36% 的格子下结论

- 学生 × 指标共 **360 个格子**；
- 只有 **130 个（36.1%）** 达到 **≥3 条已评分证据**的门槛；
- 其余一律输出 `证据不足`，**不输出掌握/薄弱**。

这直接回应赛题那句"避免将缺少记录直接解释为未掌握"——甚至更进一步：**没有记录时我们也不说"已掌握"**。例如 D17 只有 4 条记录，界面显示"0/9 指标可判定"，而不是"整体掌握度 66%"。

> 这一点是整个系统最"抗问"的设计：评委随便抽查一个学生，结论都能落到记录编号上。

### 4.3 错因归因：385 条，六类

| 类型 | 条数 | 占比 |
|---|---|---|
| C1 概念误解 | 174 | 45.2% |
| C3 计算失误 | 94 | 24.4% |
| C6 级联错误 | 49 | 12.7% |
| C4 步骤遗漏 | 32 | 8.3% |
| C5 表达不规范 | 27 | 7.0% |
| C2 符号错误 | 9 | 2.3% |

每条都带：`记录编号 / 题号 / 指标 / 得分点 / 类型 / 说明`。并且能定位到**评分点级**的共性难点，例如 `Q043P2`（除以负数变号）在 9 名作答者中 0 人正确——这类"步骤级"结论比"不等式薄弱"有用得多。

### 4.4 群体层面

- 班级对比：DC01 总体 **60.0%** vs DC02 **55.4%**，差异集中在 T02（方程与方程组）：61.1% vs 49.3%；
- 主题层面：T03 不等式 68.0% 最好，T02 最弱；
- 跨节点变化：37 组"进步/退步/顽固错误"，用于说明学习演进；
- **班级 × 题目 / 班级 × 评分点**（`statistics.json` 新增两维）：可直接回答"某个班在某个评分点上差多少"，讲评时能精确到步骤；
- **解题过程覆盖**：790 条里有 **260 条（32.9%）** 记录了文字解题过程；其余"未记录"是**源数据没有提供**，不代表学生没写步骤——这一点写进了产物注释，避免被误读。

> PPT 建议：一张"40×9 热力图（空白=证据不足）"+ 一句"我们不给没数据的格子涂颜色"。

### 4.5 口径与产物契约（防"各算各的"）

- 所有产物字段含义、计算口径、缺失语义都写在 **`docs/产物数据契约.md`**（队友新增，151 行），评审可以逐字段核对；
- 关键口径三条：①得分率 = Σ得分/Σ满分（不是得分率取平均）②证据门槛 3 条 ③过程缺失 ≠ 步骤缺失；
- `verify.py` 现在有 **15+ 项断言**，除总量外还校验：8 条质量规则命中数、逐条过程状态与文本一致、班级聚合与记录汇总一致、跨节点标签可读性等。

## 5. 任务 3 的实现：可执行的个性化建议

### 5.1 产物结构（`task3_recommendations.json`）

```
meta            ：口径、阈值、生成方式
cases           ：3 个典型案例（D37 困难 / D15 优秀 / D24 中等）
all_students    ：37 人的轻量建议
class_advice    ：班级层面教学建议（含 DC01/DC02 差异）
```

每个案例的建议条目包含：**优先级 → 指标 → 理由（掌握度 + 证据数）→ 推荐题目 → 分步提示 → 过关条件**。

### 5.2 三条硬约束（也是赛题的硬要求）

1. **提示不给答案**：分步提示是"脚手架式提问"，生成后还要过一道**答案泄露检测**（把题目参考答案逐字比对，命中即替换为安全版本）——本次生成命中 **0 条**；
2. **材料必须可指认**：建议里的题目、学习卡都来自赛题提供或规则登记的材料，不虚构资源；
3. **必须能调整**：每条建议带 `follow_up_condition`（如"同指标再答对 2 题、其中 1 道解答题"→ 进入下一优先级；否则回退）。

> PPT 建议：用一个案例做"三栏对照"：左边学习要求、中间已有表现（带证据条数）、右边建议（题号 + 提示 + 过关条件）。这正是赛题"结果核对要求"要的对应关系。

## 6. 智能体层（07V2）：从"问答"到"调度"

| 能力 | 实现 | 为什么重要 |
|---|---|---|
| **规则路由** | 关键词意图表 → 诊断/建议/讲评/班级 | 零成本、确定性、可解释，不用 LLM 做调度 |
| **会话记忆** | 记住 `current_student` / 上次意图 | 支持"他呢？""再详细点"这类指代消解 |
| **复合级联** | 一句话同时命中诊断+建议 → 依次执行，上一步结果注入下一步 | 例如"D01 哪里薄弱，顺便说说该练什么"→ 8 步链 |
| **讲评 Agent** | 必讲评分点 Top3 + 两班差异 + 教学话术 | 教师端真正想要的是"下周讲什么" |
| **执行轨迹 Trace** | 每步记录 `agent/action/detail/output/time` | 答辩可现场展开"它到底怎么想的" |
| **校验 Agent（四道闸门）** | ①结论必须带证据 ID ②证据<3 不得判薄弱 ③提示不得含答案 ④统计须与诊断一致 | 把"不许胡说"写进代码而不是写进提示词 |

实测五类问法全部正确路由：

```
D01哪里最薄弱？                   → DiagnosisAgent          4 步  校验通过
D01哪里薄弱，顺便说说该练什么     → Diagnosis + Recommend   8 步  校验通过
下周这个班该怎么讲？               → LectureAgent           4 步  校验通过
两个班差在哪？                     → ClassAgent             3 步  校验通过
他呢？                             → DiagnosisAgent          4 步  校验通过（记忆生效）
```

## 8. 本地大模型：为什么"只让它管表达"

### 8.1 方案

- 后端：**Ollama + `deepseek-r1:8b`**（自动探测本机模型），OpenAI 兼容接口也保留，可一键切回云端；
- 关键取舍：**关闭思考链（think=false）+ 草稿改写**，而不是让模型自由作答。

### 8.2 为什么这样做（这是最值得讲的技术判断）

直接把事实丢给 8B 推理模型，它会输出"首先，用户的问题是……我需要只使用事实……"这类**自我对话**，而且数字容易漂。我们的解法是两段式：

```
① 规则从事实里生成"不会错"的草稿（掌握度、证据数、指标名）
② 模型只负责把草稿改写成"学伴口吻"
③ 数字守卫：改写结果若出现草稿里没有的数字、或编造指标编号 → 整条丢弃，直接用草稿
```

效果对比（同一问题 D01）：

- 直连模型：1000+ 字自我对话，没给结论；
- 现方案：**"你最薄弱的是 T01I3 用整式解释具体问题，掌握度 29%，有 3 条证据支持……"**

### 8.3 实测数据

| 指标 | 数值 |
|---|---|
| 批量诊断 173 条解答题 | **173/173 成功，0 失败**，约 **3.9 秒/条**，总计约 11 分钟 |
| 与规则初判同类型 | 89%（154/173） |
| 明确"同意初判" / "改判" | 148 条（86%）/ 25 条（14%），**每条改判都带理由** |
| 典型改判 | 规则判 C1 → 模型判 C2 符号错误，理由："解 x+1>3 时算成 x>4" |
| 关闭思考链提速 | 1.5 s vs 9.5 s（约 6 倍） |

> 这组数据能支撑一个很强的答辩观点：**我们不是"用了大模型"，而是"给大模型装了护栏"**。

## 9. 创新点（建议 PPT 单独一页，逐条一句话 + 一个数字）

1. **证据门控（Evidence-Gated Mastery）**
   n<3 一律 `insufficient`，360 个格子里只给 130 个下结论。把"信息不足"做成系统的一等公民，而不是文档里的一句免责声明。

2. **规则算事实、模型管表达的双层架构**
   规则可复算，模型可解释；数字守卫 + 指标白名单，改写不许改数字。173 条实测：89% 一致、14% 改判且全部附理由。

3. **多智能体协同 + 全链路轨迹**
   规则路由（不用 LLM 调度）+ 会话记忆 + 复合级联 + 四类专职 Agent；每步落 Trace，答辩可逐条回放。

4. **校验 Agent 的四道闸门**
   证据 ID、阈值、不泄答案、统计一致性——把赛题口径翻译成可执行的断言，违反即拦截。

5. **证据密度显式化**
   任务 1 的每个指标都标"高/中/低"证据密度（1/5/3），让"哪些结论能信"一眼可见。

6. **评分点级归因**
   不满足于"这道题错了"，而是定位到"Q043 第 2 个评分点（负数变号）9 人全错"——教学动作因此可以直接落到步骤上。

7. **离线优先的工程化**
   本地模型 + 单文件 exe + 一键流水线（7 条核心步骤）+ 15 项产物校验；断网可演示，评委可现场复跑。

8. **教学闭环而非三张皮**
   三任务共用 9 指标主键：内容梳理 → 证据诊断 → 练习建议，同一条链上前后引用。

## 12. 边界与局限（主动讲，反而加分）

1. **样本小**：40 人、790 条记录，只够做"方法演示"，不足以训练预测模型；
2. **证据稀疏**：63.9% 的"学生×指标"格子 ≤2 条证据，因此系统大面积输出"证据不足"，这是**设计的诚实**，不是缺陷；
3. **8B 模型能力有限**：语义归因可用，但开放问答容易跑偏 → 因此限定"草稿改写 + 数字守卫"；
4. **不提真实成效**：赛题明确"不要求用模拟数据证明真实教学成效"，我们所有结论都标注为"基于模拟数据的分析"。

## 13. 答辩问答预案

**Q1：你们的"掌握度"是怎么算的？**
A：BKT 四参数模型 + 部分得分软证据，先验取全局题目表现；但**只在证据 ≥3 条时输出**，否则 `insufficient`。我们不把先验值当结论。

**Q2：凭什么说这个学生薄弱？**
A：点开任意结论能看到 `记录编号 → 题号 → 评分点得分`。例如 D01 的 T01I3 掌握度 29%，由 Q011/Q018/Q021 三条记录支撑。

**Q3：大模型会不会瞎说？**
A：会，所以我们不让它碰数字。规则先生成草稿，模型只改口吻；改写后若出现新数字或编造指标编号，整条丢弃。实测 89% 与规则一致，14% 改判全附理由。

**Q4：任务 2 要求的"信息不足"你们怎么体现？**
A：360 个格子里 230 个（63.9%）证据 ≤2 条，系统全部标为"证据不足、不下结论"；界面里这类格子留白，不涂颜色。

**Q5：换成别的学校/别的班能用吗？**
A：能。所有阈值（证据门槛 3、分级 0.7/0.4）与路径都在配置与环境变量里，产物目录可替换；`verify.py` 会校验新数据的关键统计。
