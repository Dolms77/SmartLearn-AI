# Output 数据契约（前端交接）

本文说明 `output/` 根目录中数据文件的生成来源、字段含义、页面用途及前端消费方式。文件名和既有字段保持兼容；新增字段采用增量扩展。

## 1. 使用约定

- 所有 JSON 均为 UTF-8。前端按字段 ID 关联数据，不依赖 JSON 对象的展示顺序。
- `cleaned_data.json` 是逐条作答及知识结构的主数据；`statistics.json` 是统计结果；其他文件由各模块生成。
- 页面展示优先使用明确的中文展示字段；机器枚举用于逻辑判断，不应直接展示原始 code。
- `score` 表示源 CSV 当前录入的得分，不代表已通过人工复核。出现 `quality_flags` 时应展示复核提示，不能默认为有效成绩。
- 不得把空的 `student_process` 显示成学生没有解题步骤；它表示源数据未记录过程文本。
- 当前界面从仓库根目录 `output/` 读取 JSON，并根据文件修改时间和大小刷新缓存。更新产物后，在 Streamlit 页面点击 **Rerun** 即可重新加载。

## 2. 任务一：知识结构与来源追溯

### `task1_knowledge_structure.json`

- **生成源**：`已完成脚本/09_task1_knowledge_structure.py`，读取 `cleaned_data.json`。
- **内容**：3 个主题、9 个指标、题目映射、满分、题型数量及作答证据密度。
- **来源定位**：
  - `themes.{theme}.indicators.{indicator}.curriculum_source`：课标整理编号、来源 CSV 行及课标页码引用。
  - `...textbook_source`：教材页码范围及其来源。
  - `...question_ids`：题目 ID 列表。
  - `...question_references`：题目 ID 对应的 `题目与材料.csv` 行号和资料来源。
- **关联题目详情**：使用 `question_id` 连接到 `cleaned_data.json` 的 `question_indicator_map[question_id]`，可取题干、选项、参考答案、解析、评分点和资料来源。
- **界面用途**：任务一页面由 `ui/adapter.py` 的 `knowledge_rows()` 优先读取该文件；页面提供结构表格和导出。缺失时才回退到 `cleaned_data.json`。

`课程要求.csv` 提供课标整理编号、课标页码引用和教材页码范围，但当前输入数据没有课标原文或教材摘录。因此产物只提供可追溯引用，不臆造原文。字段 `full_text_available`、`excerpt_available` 为 `false`。
`source_row` 是原始 CSV 的物理行号（含表头，因此首条数据为第 2 行）。

## 3. 任务二：作答、评分点和班级统计

### `cleaned_data.json`

- **生成源**：`已完成脚本/01_data_loader.py`；来源为赛题 CSV。
- **使用者**：02 BKT、03 错因诊断、04 RAG、05 图谱、07 多智能体、08 任务三、09 任务一及 Streamlit 界面。
- **界面用途**：学生作答、过程状态与文本、评分点逐项得分、数据质量提示、知识结构、题目详情、测验节点信息。
- **主要路径**：
  - `knowledge_structure`：主题、目标、课标编号/引用、教材页码及来源行。
  - `question_indicator_map`：题目 ID 到指标/主题、题干、答案、评分点、资料来源及 CSV 行号。
  - `records[]`：去重后纳入统计的已评分记录。含学生、班级、题目、节点、原始得分、最终作答及过程。

本轮增补字段：

| 字段 | 含义 |
|---|---|
| `records[].student_process_status` | 稳定枚举：`recorded` / `not_recorded` |
| `records[].student_process_status_label` | 展示值：`已记录` / `未记录` |
| `records[].scoring_point_details[]` | 结构化评分点：ID、定义、得分及满分 |
| `records[].quality_flags[]` | 该记录命中的质量规则 ID；详情见质量报告 |
| `question_indicator_map.{question_id}.source` | 题目与材料表中的资料来源 |
| `question_indicator_map.{question_id}.source_file/source_row` | 来源文件名和 CSV 行号 |
| `question_indicator_map.{question_id}.scoring_point_definitions` | 评分点 ID 到定义及满分的映射 |

`data_quality_report.json.process_coverage` 显示本批次有 260/790 条记录提供了文字解题过程（约 32.9%）。其余 530 条标记为“未记录”，不推断其实际解题步骤。

### `statistics.json`

- **生成源**：`已完成脚本/01_data_loader.py`。
- **使用者**：02、03、05、06、07、08 及界面班级分析。
- **主要分区**：`overall`、`by_theme`、`by_indicator`、`by_scoring_point`、`by_student`、`by_class_theme`、`cross_node_changes`。
- **本轮新增**：
  - `by_class_question.{class_id}.{question_id}`：每班每题的记录数、得分、满分和得分率。
  - `by_class_scoring_point.{class_id}.{scoring_point_id}`：每班每评分点的记录数、得分、满分和得分率。
  - `cross_node_changes[].change_type_label`：机器枚举对应的中文展示值。保留 `change_type` 供程序判断。
  - 当前班级页按所选班级展示逐题统计和得分率最低的 20 个评分点。

跨节点变化应显示 `change_type_label`，不要直接展示 `persistent_error` 等机器值。若旧版文件没有该字段，可用 `change_type` 映射展示，但应保留原始 code。

## 4. 数据质量规则与当前处理口径

`data_quality_report.json.source_quality_audit.checks[]` 对 806 条原始记录逐条复核，包含 `rule_id`、`name`、`hit_count`、完整 `record_ids` 和 `disposition`。命中数是“记录-规则”次数，不同规则可能命中同一条记录。

| 规则 | 本批次命中 | 当前处理 |
|---|---:|---|
| R1 得分超过满分 | 2 | 原始得分保留并标记，不自动截断或重算 |
| R2 评分点得分之和与总分不一致 | 3 | 原始总分和评分点均保留并标记，不自动重算 |
| R3 同一作答事件有多个版本 | 14 行 / 7 组 | 统计采用最新的已评分版本；各版本 ID 保留在报告 |
| R4 待评分 | 6 | 不纳入已评分统计，单独记录 |
| R5 未作答 | 5 | 不作为答错或掌握度证据 |
| R6 题目不在对应测验节点范围 | 1 | 标记，不自动更改节点或删除 |
| R7 记录主题与题目主题不一致 | 1 | 保留源主题并标记，不自动修正 |
| R8 填空答案与参考答案一致但得分为零 | 1 | 标记待复核，不自动改分 |

当前存在的成绩冲突：

- `DR0361`：录入 10/1，评分点合计 1（R1、R2）。
- `DR0535`：录入 4/3，评分点合计 3（R1、R2）。
- `DR0133`：录入 3/3，评分点合计 2（R2）。

按已确认范围，这些记录本轮不自动改分。`cleaned_data.json` 的 `score` 和基于它计算的统计仍使用源 CSV 录入总分；前端应通过 `quality_flags` 提示“待复核”，不能将其描述为已校正成绩。后续若决定依据评分点重算，需要同步重跑所有依赖统计的下游产物，避免不同文件口径不一致。

待评分和未作答记录不进入 `cleaned_data.json.records`，其 ID、学生、题目和节点信息分别保存在质量报告的 `pending_records`、`unanswered_records` 与质量规则明细中。

### 05 知识图谱

`knowledge_graph.html` 是 05 从清洗数据和任务一结构生成的交互式图谱。图中包含课标、主题、观察指标、题目、学习卡、教材等节点及其对应关系，可用于查看知识结构和题目映射。它不是 UI 读取字段的来源；当前界面把此文件作为可选预览/下载附件。图谱预览内部可能依赖 HTML 引用的 CDN，离线时可下载后在支持联网的浏览器中打开。

### 06 仪表盘（供前端参考，不由默认流程生成）

`06_dashboard.py` 当前草稿生成 8 类图表。该 HTML 不再作为 `output/` 的常规交付文件；前端可用 `statistics.json`、`student_profiles.json`、`mastery_matrix.json` 和 `error_pattern_summary.json` 实现相同或调整后的可视化：

| 图表 | 推荐数据来源 | 含义 |
|---|---|---|
| 九指标得分率雷达图 | `statistics.json.by_indicator` | 比较九个观察指标的整体表现 |
| 班级 × 主题对比 | `statistics.json.by_class_theme` | 比较不同班级在三个主题上的得分率 |
| 评分点得分率条形图 | `statistics.json.by_scoring_point` | 定位具体评分点的相对薄弱处 |
| 学生得分率分布 | `statistics.json.by_student` | 查看学生得分率分布，不替代证据门槛判断 |
| BKT 掌握度矩阵气泡图 | `student_profiles.json` / `mastery_matrix.json` | 教师班级概览按班级展示学生 × 指标掌握度；气泡大小/颜色编码掌握度，灰色空心点表示证据少于 3 条；可按学生与指标平均掌握度排序 |
| 错因类型分布 | `error_pattern_summary.json.by_error_type` | 展示 C1–C6 等错因数量与占比 |
| 跨节点变化 | `statistics.json.cross_node_changes` | 比较同一学生同一道题在 N01、N02 的变化，展示 `change_type_label` |
| 关键发现卡片 | `error_pattern_summary.json.critical_findings` | 展示规则生成的高优先级发现 |

上表是前端图表设计说明，不表示这些图已经集成到当前 Streamlit UI。02 的掌握度与 01 的原始得分率是不同口径，图表标题和提示应明确区分。

## 6. 典型前端读取方式

```javascript
const question = cleaned.question_indicator_map[record.question_id];
const pointResults = record.scoring_point_details ?? [];
const processWasRecorded = record.student_process_status === "recorded";
const warnings = record.quality_flags ?? [];

const classQuestion = statistics.by_class_question[classId]?.[questionId];
const classPoint = statistics.by_class_scoring_point[classId]?.[pointId];
```

使用 `question_id`、`indicator_id`、`scoring_point_id`、`rule_id` 关联；展示层使用 `student_process_status_label`、`change_type_label` 和质量规则 `name`。不要在使用者页面直接展示 `persistent_error`、`not_recorded` 等机器 code。
