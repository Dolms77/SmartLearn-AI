# 「智慧学伴」AI 学习助手 —— 技术方案与实施指引

> 目标：用**开源模型 + 自训练**构建一个可离线运行、结论可追溯的学情诊断与个性化学习智能体，覆盖赛题三项核心任务，并产出 5 项提交物。
>
> 本机实测条件（2026-11-15）：RTX 4060 Laptop **8 GB 显存**、Windows、C 盘可用 116 GB / D 盘 133 GB、无 conda、Python 3.7/3.13 各一份、**当前 shell 访问 pypi / huggingface / modelscope 均超时**（需配置镜像或离线拷贝）。
>
> 本方案按 8 GB 显存设计，所有模型均可本机跑完训练与推理。

## 0. 先做一个关键判断：该训练什么、不该训练什么

评审 80% 权重在**材料准确性、依据充分性、建议合理性**。因此分工必须是：

| 能力 | 由谁承担 | 为什么 |
|---|---|---|
| 统计、得分率、覆盖度、掌握度分级 | **规则引擎 + SQL/pandas（确定性）** | LLM 算数必然出错，而这类错误在评审眼里是致命伤 |
| 材料检索与页码引用 | **向量库 + BM25（RAG）** | "材料出处"是硬性要求，必须来自真实切片 |
| 题目↔指标标注 | 微调小模型 + 规则校验 | 54 题量小，可用少量样本教会格式 |
| 错题归因（"不会"vs"粗心"vs"未作答"） | **微调模型 + 评分点规则** | 需要读"解答过程"，纯规则覆盖不全 |
| 学习建议 / 分步提示 / 讲评稿生成 | **微调后的 7B 模型** | 这是唯一真正需要"语言能力"的环节 |
| 输出一致性 | **JSON Schema + 约束解码 + 后校验** | 保证可机读、可复核 |

**结论：不要训一个"什么都会"的模型。**要训的是 **1 个生成模型（LoRA）+ 1 个检索模型（可直接用，可选微调）+ 1 套规则引擎**。这也是《创新点.xlsx》里"RAG + 规则引擎 + 结构化数据库混合架构"的正确落地方式，能直接对上"减少幻觉、结论强制引用"这一创新点。

```

└───────────────┬─────────────────────────────────────────────┘
                │
┌───────────────▼──────────────┐   ┌──────────────────────────┐
│ 编排层 Orchestrator          │   │ 输出契约 JSON Schema      │
│ ①清洗 → ②聚合 → ③检索        │◄──┤ (content_map / diagnosis │
│ → ④生成 → ⑤校验 → ⑥落库      │   │  / advice)               │
└───┬──────────┬───────────┬───┘   └──────────────────────────┘
    │          │           │
┌───▼────┐ ┌───▼──────┐ ┌──▼─────────────┐
│规则引擎│ │RAG 检索   │ │生成模型 (LoRA)  │
│清洗/聚合│ │BGE-M3+BM25│ │Qwen2.5-7B-Instruct│
│/分级   │ │+Reranker  │ │4bit + GGUF 部署 │
└───┬────┘ └───┬──────┘ └──┬─────────────┘
    │          │           │
┌───▼──────────▼───────────▼──────────────────────────────────┐
│ 数据层 DuckDB/SQLite：6 张原始表 + 4 张派生表                 │
│ (clean_log / indicator_mastery / evidence_index / advice_log)│
└──────────────────────────────────────────────────────────────┘
```

**四条硬规则（写进代码，不靠模型自觉）**
1. 任何结论必须携带 `record_ids` 或 `material_ids`，否则校验失败、拒绝输出。
2. 引用只能来自检索白名单（B02/B05/B06 + L01–L03 + 54 题号），模型编造的编号一律丢弃。
3. 证据量 < 阈值（建议 3 条）时，`mastery` 只能是 `insufficient`，禁止输出"未掌握"。
4. 讲解/提示禁止出现最终答案字符串（用题目表 `参考答案` 做正则比对拦截）。

### 3.2 清洗规则（配置文件驱动，评测集可复用）

`config/clean_rules.yaml`：

```yaml
rules:
  - id: R1_score_overflow          # 得分 > 满分
    action: cap_to_full_mark
    flag: anomaly_score
  - id: R2_points_mismatch          # 评分点之和 ≠ 总分
    action: recompute_from_points
    flag: anomaly_points
  - id: R3_latest_revision          # 同一作答事件取最大 修订版本
    action: keep_latest
  - id: R4_pending_isolated         # 待评分：保留但不进入得分统计
    action: exclude_from_scoring
  - id: R5_blank_vs_unanswered      # 未作答 ≠ 未掌握
    action: tag_status
  - id: R6_node_scope_check         # 题目不在节点"可用题目编号"内
    action: flag_out_of_scope
  - id: R7_topic_mismatch           # 记录主题 ≠ 题目主题
    action: fix_from_item
  - id: R8_answer_equals_ref_but_zero  # 作答=参考答案却 0 分
    action: flag_grading_conflict
```

### 3.3 派生表（任务 2 的骨架）

```sql
-- 1) 有效作答（去修订、去待评分）
CREATE TABLE eff AS SELECT * FROM 作答记录
WHERE 修订版本 = (SELECT MAX(修订版本) FROM 作答记录 r2
                 WHERE r2.作答事件编号 = 作答记录.作答事件编号);

-- 2) 指标体系（9 行）
CREATE TABLE indicator AS SELECT * FROM 课程要求;

-- 3) 个体×指标 掌握度
CREATE TABLE mastery AS
SELECT 学生编号, 指标编号,
       COUNT(*) AS 证据数,
       SUM(得分)*1.0/SUM(满分) AS 得分率,
       AVG(CASE WHEN 得分=满分 THEN 1 ELSE 0 END) AS 满分率,
       MAX(节点编号) AS 最近节点,
       CASE WHEN COUNT(*) < 3 THEN 'insufficient'
            WHEN SUM(得分)*1.0/SUM(满分) >= 0.85 THEN 'A'
            WHEN SUM(得分)*1.0/SUM(满分) >= 0.60 THEN 'B'
            ELSE 'C' END AS 等级
FROM eff JOIN 题目与材料 USING (材料编号)
WHERE 评分状态='已评分' GROUP BY 1,2;

-- 4) 证据索引（结论 → 记录）
CREATE TABLE evidence_index(证据ID, 学生编号, 指标编号, 记录编号, 得分, 满分, 评分点得分);
```

**关键设计：`证据数` 是显式字段**，输出里必须带。这样"D17 只有 4 条记录"会自然呈现为 `insufficient`，天然满足"避免将缺少记录直接解释为未掌握"。

### 3.4 错题归因规则（先规则、后模型）

把 `评分点得分` 的得失模式映射到错因（这是任务 2 "问题识别与依据"最出彩的部分）：

| 模式 | 归因标签 | 例 |
|---|---|---|
| P1=0 且 P2=P3=0 | 起点性错误（列式/去括号未建立） | Q014 全 0 |
| P1=1, P2=0, P3=0 | 中段中断（合并同类项/移项） | Q025 去分母对、合并错 |
| P1=1, P2=1, P3=0 | **收尾缺失（未检验/未写范围/未答）** | 大量 Q006/Q011/Q018 |
| 得分=满分 但 步骤数≤3 | 结论对但过程简（提示写全步骤） | 少数 |
| 状态=待评分 | 不计入能力，标"待复核" | 4 条 |
| 状态=未作答 | 不是错答，标"无作答记录" | 5 条 |

已实测：解答题步骤数与得分强相关（2 步→1.27 分、4 步→1.74、**5 步→2.87**、6 步→3.20），即"补上检验/作答一步"是满分分水岭——可直接作为"必须写检验"建议的量化依据。

## 4. 阶段三：RAG 知识库（1.5 天）

### 4.1 解析与页码对齐（最容易错的一步）

```python
# src/parse_pdf.py
import fitz  # pymupdf
# 课标：PDF 页码 = 正文页码 + 7（实测 PDF p62 = 正文 p55）
# 教材：B05 PDF p1 = 印刷 p68 → 偏移 = 67（每个切片单独标定）
```

每块 chunk 必须携带元数据：

```json
{"chunk_id":"B05-012","file":"B05_相关资料切片.pdf","pdf_page":12,"print_page":79,
 "chapter":"第四章 整式的加减","section":"4.2 去括号","topic":"T01","indicator":["T01I2"],
 "text":"去括号时，如果括号外的因数是负数，去括号后原括号内各项的符号都要改变……"}
```

### 4.2 切块策略

- 教材：按"章 → 节 → 段"切，单块 300–500 字，重叠 50 字；例题与"归纳"框单独成块（建议时最好引用）。
- 课标：按编号条目切（如"③掌握等式的基本性质……"整条一块），chunk 里带 `CR01/CR02/CR03` 与正文页码。
- 学习卡 L01–L03：整卡一块，标 `type=hint_card`（用于"分步提示"）。

语料很小（约 800–1200 块），**用 SQLite + faiss 即可，不需要向量数据库服务**。

### 4.3 混合检索

```python
score = 0.6 * dense(bge-m3) + 0.4 * bm25(jieba)   # RRF 融合更稳
top_k = 8 → bge-reranker 重排 → 3 条入 prompt（附 chunk_id 与页码）
```

**引用必须回填**：模型只允许输出 `[B05 p12]`、`[Q015]`、`[L01]` 这类**已检索到的 id**，生成后正则校验，不在白名单的直接替换为最近邻合法 id 并记一次 `citation_repair`（这个计数可以写进创新点：引用约束率）。

## 5. 阶段四：训练数据构造（3 天，决定成败）

### 5.1 四类样本

| 类型 | 数量目标 | 来源 | 构造方式 |
|---|---|---|---|
| **T-A 题目→指标** | 300–500 | 54 题 + 教材例题 | 强模型生成候选 + 人工/规则校验（题目主题已知，指标由 `指标编号` 字段给出，主要学"解释为什么"） |
| **T-B 过程→归因** | 500–800 | 260 条解答题有效记录 | 用"评分点模式 → 归因标签"规则生成 seed，再由强模型扩写成自然语言诊断 |
| **T-C 建议生成** | 600–1000 | 指标×表现组合（9 指标 × 4 档表现 × 3 题型） | 强模型按固定三段式生成 + 人工抽检 10% |
| **T-D 分步提示（不给答案）** | 400–600 | 54 题 × 提示层级（第 1 层方法、第 2 层关键步、第 3 层自我检查） | 强模型生成 + 用正则拦截答案 |

**扩充技巧**：把 3 个主题的指标、题型、错因做笛卡尔积，能稳定扩到 2–3k 条；再用**公开数据做留出验证**（按学生 8:2 切，绝不用测试学生训练）。

### 5.2 统一对话格式（ShareGPT / messages）

```json
    {"role":"user","content":"【学生】D19\n【指标】T01I2 识别同类项、去括号并化简（证据数 3，得分率 0.33）\n【证据】Q015 得分 0/3，评分点 Q015P1=0,Q015P2=0,Q015P3=0；作答过程：原式=6a-3b-2a-4b → =4a-7b\n【可用材料】B05 p12(印刷79) 去括号法则；L01 学习卡；Q005、Q009\n请给出学习建议。"},
    {"role":"assistant","content":"{\"student\":\"D19\",\"indicator\":\"T01I2\",\"diagnosis\":{\"summary\":\"去括号时括号前为负号，第二项符号未改变\",\"evidence\":[\"Q015\"],\"confidence\":\"中\"},\"advice\":[{\"step\":1,\"content\":\"...\",\"materials\":[\"L01\"],\"hints\":[\"...\"],\"success_criteria\":\"Q009 独立完成得 3 分\"}],\"follow_up\":\"...\"}"}
}
```

### 5.3 数据质量红线

- 每条样本的 `materials` 必须是真实存在的编号（写脚本校验）；
- 建议中不得出现 `参考答案` 原文（脚本比对）；
- 对"证据不足"样本要占 **≥15%**，否则模型学不会说"信息不足"——这是本题最容易翻车的地方；
- 训练集不包含测试学生（D 编号留出），防止"背答案"。

### 6.2 任务 1：内容与要求梳理

| 字段 | 例 |
|---|---|
| 主题 / 指标 | T01 / T01I2 识别同类项、去括号并化简 |

> 把"证据密度"作为一列，是本题的加分动作：它让评审一眼看到你知道哪些结论可靠、哪些不可靠。（实测 T01I3 仅 2 题、T03I3 仅 4 题。）

### 6.3 任务 2：学情分析

个体摘要固定五段（全部挂证据）：

1. **证据概况**：有效记录 n 条 / 覆盖指标 k/9 / 缺失主题；
2. **已确定表现**：指标级得分率与满分率（仅当证据数 ≥3）；
3. **关键问题**：按错因标签聚合，附 2–3 条代表性 `记录编号`；
4. **不能确定**：`insufficient` 指标清单 + 原因（无记录/待评分/题量不足）；
5. **班级参照**：该生 vs 班级均分差（DC01/DC02 分别）。

群体摘要：班级×主题得分率、指标得分率排序、共性薄弱题 Top5、班级差异题 Top5。

已实测可直接引用的结论：总体 填空 0.587 / 解答 0.554 / 选择 0.833；T01 0.587、T02 0.557、T03 0.679；DC02 在 T02 上 0.483 vs DC01 0.624。
